# 书签标签自动分组（Bookmark Tab Grouper）

Chrome 扩展：**从书签打开的标签页会自动进入标签组，组名就是书签所在文件夹的名字**。同一个文件夹里的书签都进同一个组。

## 安装

1. 打开 `chrome://extensions`，打开右上角的「开发者模式」
2. 点「加载已解压的扩展程序」，选择 `extension/` 目录
3. 改完代码后，在扩展卡片上点刷新按钮 ⟳

## 效果

| 操作 | 结果 |
|---|---|
| 从书签栏 / 书签菜单打开书签（左键、中键、Cmd+点击、右键「全部打开」） | 进入以书签文件夹命名的标签组 |
| 在书签管理器 `chrome://bookmarks` 里双击、选中多个后打开 | 同上 |
| 继续打开同一文件夹的书签 | 加入已有的组，不会再建一个 |
| 同时打开一个文件夹里的多个书签 | 只建 1 个组 |
| **飞书文档 / 表格 / 多维表格 / 知识库 / 幻灯片等书签，不论放在哪个文件夹** | **统一进入「文档」组（优先于按文件夹分组）** |
| **不是从书签打开的飞书文档**：网页里点链接（同标签或新标签）、地址栏输入、飞书客户端跳转、飞书网页内切换到文档、登录后跳回文档 | **同样进入「文档」组** |
| 普通链接、手动输入网址、刷新、前进/后退 | 不处理（飞书文档除外） |
| **前进 / 后退** | **标签回到该页面当时所在的组**：例如文档组 → 同一标签从书签打开 Work 书签（进入 Work 组）→ 后退，会回到文档组 |
| 在组里的页面上点站内链接 | 留在原组 |

## 设置（点工具栏图标打开）

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 总开关 | 开 | 关掉后插件不做任何操作 |
| 分组依据 | 所在文件夹 | 「顶层文件夹」：`工作/文档/xx` 归入「工作」组 |
| 组名格式 | 文件夹名 | 「完整路径」：组名显示为 `工作 / 文档` |
| 根目录下的书签 | 不分组 | 直接放在书签栏上的书签；可改为归入「书签栏」组 |
| 已在其他组时也移动 | 开 | 关掉后，如果标签已经在你自己建的组里，不会被移走 |
| 每个文件夹固定颜色 | 开 | 同一文件夹的组颜色始终相同 |
| 文件夹改名后同步组名 | 开 | 你手动改过名字的组不会被覆盖 |
| 前进 / 后退时恢复原分组 | 开 | 关掉后，前进/后退不改变分组 |
| 飞书文档等统一归入 | 开 | 规则分组，优先于按文件夹分组；关掉后飞书文档也按文件夹分组 |
| 文档组名 | 文档 | 修改后，已经存在的文档组会同步改名 |
| 文档规则生效范围 | 任何方式打开 | 改成「仅书签打开」后，只有从书签打开的飞书文档才归组 |
| 已打开的文档：立即整理 | — | 按钮。把所有窗口里还没分组的飞书文档标签一次性归入文档组 |

弹窗下方会显示最近 30 条分组记录，方便排查。

## 文档规则

满足下面两个条件的书签，归入「文档」组。书签原网址、跳转前或跳转后的网址，任意一个满足就算：

- **域名**：`feishu.cn`、`feishu.net`、`larkoffice.com`、`larksuite.com`，以及它们的子域名，例如 `bytedance.larkoffice.com`、`xxx.feishu.cn`
- **路径第一段**（不区分大小写）：

| 路径 | 类型 |
|---|---|
| `/docx/` `/doc/` `/docs/` | 文档（新版、旧版） |
| `/wiki/` | 知识库 |
| `/sheets/` `/sheet/` | 电子表格 |
| `/base/` `/bitable/` | 多维表格 |
| `/slides/` | 幻灯片 |
| `/mindnote/` `/mindnotes/` | 思维笔记 |
| `/file/` `/drive/` | 云盘文件、文件夹 |
| `/board/` | 画板 |
| `/share/<以上类型>/` `/space/<以上类型>/` | 分享页、旧版路径，如多维表格表单 `/share/base/form/...` |

以下页面**不算文档**，仍按文件夹分组：飞书官网首页、开放平台 `open.feishu.cn/document/...`、妙记 `/minutes/`、日历、`applink`。

其他特点：

- 文档组固定为蓝色，所有窗口用同一个组名。
- 直接放在书签栏根目录的飞书文档也会归入文档组，不受「根目录下的书签」设置影响。
- 文档跳转到登录页时，按书签原网址判断，仍归入文档组。

### 非书签打开的文档

为了不打乱你自己整理好的标签，从书签以外的地方打开飞书文档时，规则比书签打开更保守：

| 情况 | 行为 |
|---|---|
| 标签未分组，或在本插件建的组里 | 归入文档组 |
| 标签在**你自己建的组**里 | 不移动 |
| 你把某个文档标签**手动移出了组**，或取消了分组 | 这个标签之后打开其他文档也**不再自动归组**；新开的标签照常归组 |
| 刷新、前进/后退、浏览器重启后恢复的标签 | 不触发；已经打开的文档用「立即整理」 |
| 在这个标签里从书签打开 | 照常归组。从书签打开视为明确意图，不受“手动移出”的限制 |

实现上监听了以下事件：
- `webNavigation.onCommitted`：覆盖点链接、地址栏输入、客户端跳转、JS 跳转；
- `webNavigation.onHistoryStateUpdated`：飞书网页是单页应用，在站内切到文档时只触发这个事件。

插件把自己放进组的标签记在 `storage.session` 的 `placedTabs` 里，用它来判断“用户手动移出过”。

## 前进 / 后退

每个标签会记住它访问过的每个页面当时在哪个组（每个标签最多记 30 个页面，存在 `storage.session` 的 `tabHistory` 里）。记录时机有两个：离开页面时记一次，这样你手动调整过的分组也会被记下；插件刚把页面放进组后再记一次。

前进或后退回到某个页面时：

| 页面当时 | 标签现在 | 处理 |
|---|---|---|
| 在插件建的组（文档组、文件夹组） | 未分组，或在插件建的组里 | 放回那个组；组已经关掉就重建 |
| 未分组 | 在插件建的组里 | 移出组 |
| 在你自己建的组里 | 在插件建的组里 | 放回你的组；你的组已经不在就移出 |
| 任意 | **在你自己建的组里** | **不动** |
| 任意 | 未分组，并且你**手动移出过** | **不动** |
| 没有记录（插件更新前打开的页面） | 任意 | 不动 |

原则是：插件只纠正它自己造成的分组，不覆盖你的手动调整。前进/后退时也不会按书签或文档规则重新归组。

飞书网页内部用 `history.back()` 前进/后退时，触发的是 `onHistoryStateUpdated` 事件，这种情况同样会处理。

如果要支持更多域名或路径，修改 `extension/lib/core.js` 里的 `DOC_DOMAINS` 和 `DOC_PATH_PREFIXES`。

## 实现要点

- **识别「从书签打开」**有两种信号：
  1. `webNavigation.onCommitted` 的 `transitionType === 'auto_bookmark'`。覆盖书签栏和书签菜单。
  2. 书签管理器打开时，导航类型是 `link`，信号 1 不触发。这时检查网址是否精确命中某个书签，并且该书签的 `dateLastUsed` 正好在本次导航期间被 Chrome 更新过。用普通链接打开同一网址不会更新这个时间，所以不会被误判。
- **反查文件夹**：网站跳转后网址会变，所以优先用 `onBeforeNavigate` 记下的原始网址去查书签。精确查不到时再宽松匹配，忽略协议、`www.`、`#hash` 和末尾的 `/`。同一网址被多个文件夹收藏时，取最近打开的那个，其次取最近添加的。
- **找组**：每个「窗口 + 文件夹 ID」对应一个组，记在 `chrome.storage.session` 里，SW 休眠后不会丢。所以两个同名文件夹（如 `工作/文档` 和 `个人/文档`）会是两个不同的组。浏览器重启后这份记录会清空，此时按同名组接管，不会重复建组。文档组使用一个固定的虚拟文件夹 ID `__docs__`，复用同一套机制。
- **并发**：所有分组操作串行排队，避免同时打开多个书签时重复建组。
- 跳过固定标签页、弹出窗口和预渲染中的页面。用户正在拖拽标签时 Chrome 会拒绝修改，这种情况会自动重试。

## 目录结构

```
extension/            # 要加载到 Chrome 的目录
  manifest.json       # MV3；权限：bookmarks, tabs, tabGroups, webNavigation, storage
  background.js       # Service Worker：事件监听、找书签、建组/入组
  lib/core.js         # 纯逻辑函数（不依赖 chrome.*，有单元测试）
  popup/              # 设置弹窗
  icons/
scripts/make-icons.mjs  # 生成图标（不依赖第三方库）
test/unit.test.mjs      # 单元测试（node:test）
test/e2e.mjs            # 端到端测试（puppeteer-core + 本机 Chrome + 临时配置）
test/popup-shot.mjs     # 弹窗截图 + 采集运行时报错
```

## 开发命令

```bash
npm install            # 只装 puppeteer-core，用本机 Chrome，不下载浏览器
npm test               # 单元测试 + 端到端测试
npm run test:e2e       # 只跑端到端测试；HEADFUL=1 显示浏览器窗口；CHROME_PATH=... 指定 Chrome
npm run shot           # 生成 popup-screenshot.png
npm run icons          # 重新生成图标
npm run pack           # 打包成 bookmark-tab-grouper.zip（可上传 Chrome 应用商店）
```

端到端测试使用临时的 Chrome 配置目录，跑完自动删除，**不会影响你日常使用的 Chrome 数据**。飞书相关场景不访问真实飞书：测试会在本机起一个 HTTPS 服务，用自签证书和 `--host-resolver-rules` 把飞书域名指向它。

调试：在 `chrome://extensions` 的扩展卡片上点「Service Worker」打开控制台。控制台里可以用 `__btg.getGroupMap()`、`__btg.getSettings()` 查看内部状态。

## 已知限制

- 标签组不能跨窗口，所以每个窗口会各建一个同名组。
- 用书签管理器打开时，如果网站发生了跳转，依赖的是书签网址精确匹配。宽松匹配只在书签栏、书签菜单这条路径上生效。
- 书签被删除后，已有的组会保留，只是不再同步组名。
